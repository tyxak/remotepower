# RemotePower v7.4.0 — "F1nishMatters"

A release about finish.

What is already there should read, look and behave better in every theme and
every language, and each fix comes with a check that keeps it fixed. One thing
is new: Threat Intel can read the syslog of a firewall or router.

After upgrading, hard-reload the dashboard once so the new front-end loads.

## Firewall sources

A firewall or router has no agent, but it already sends its logs to RemotePower.
Under **Security → Threat Intel → Firewalls and routers** you can have the server
read them and report the addresses behind what it finds, the way it reports what
your hosts' logs show. It reads and reports; it blocks nothing on the firewall or
router. It stays off until you turn it on.

It reads refused packets from OPNsense, pfSense and MikroTik RouterOS (10 ports
or 25 packets within 30 minutes), hits on a decoy port you add to a MikroTik (two
hits, reported at once), Suricata alerts and CrowdSec alerts from OPNsense, and
failed sign-ins to RouterOS and OPNsense. The setup, the log lines it reads and
what to check when nothing shows are in
[Firewall sources: OPNsense and MikroTik](firewall-sources.md).

Only the refused-packet reader has met a real firewall, an OPNsense. The RouterOS,
Suricata and CrowdSec readers follow those products' documented formats.

## Honeypot guides

Two public guides show how to build the Worker that RemotePower's Edge sources
read:
[Run a honeypot Worker on Cloudflare](honeypot-worker.md) and
[More traps for your honeypot Worker](honeypot-traps.md).
The test suite runs each guide's script and config, and sends every line the
script prints through RemotePower's own reader.

After a review, the second guide's Worker passes your site's own `robots.txt`
answer on unchanged unless it is a file or "there is none". An outage still
tells crawlers to stay out, and the decoy lines go into every group of your
file. A login whose body cannot be read is still logged, and a WordPress site
is told which two login routes to delete.

## Wording and language

- A machine you manage is a **host** everywhere you read it: pages, buttons,
  messages, e-mails, CSV exports, the guides and the agents' own output, in all
  six languages. API paths and JSON fields keep their names (`/api/devices`,
  `device_id`). The shortcut `g d` still opens the host list.
- "3 hosts", never "3 host(s)". Card headings and buttons are in sentence case, and the names of pages are in Title Case (Threat Intel, Server Status, SSH Keys).
- Every notification reads as a sentence, and a refused request is shown in your
  language: all 991 of the server's error messages are translated into all six
  languages, and a test keeps it that way.
- A failed action says what happened, once: the server's reason, or "The server
  refused this and gave no reason.", or "The server did not answer."

## Interface

- Text is readable in every theme (WCAG AA, measured on all 13).
- The Back button goes to the page you came from, and a long press or keyboard
  focus shows tooltips in the theme's colours.
- You can use the dashboard from the keyboard: a dialog opens on its first
  field, Tab stays inside it and Escape closes it.
- Every page prints in full and fits the sheet. Nothing scrolls sideways on a
  phone, in any of the six languages.
- A page that cannot load says so and offers a retry, instead of staying on
  "Loading…".
- Every sortable table with rows can export CSV, and an address or an id in a
  table cell copies when you click it.
- The Monitor page opens at once, and a heartbeat that reports attackers no
  longer rewrites Threat Intel's whole table.

## Threat Intel

- **Count a planted credential or decoy sign-in as decided** on the Edge sources
  card (off by default) reports the address on its first hit.
- An **Addresses reported** event tells you when a sweep reported something. It
  does not page unless you turn that on.
- The log sensor keeps a slow scanner: what a pass saw of an address under 3
  requests is added to the next pass.
- Threat Intel forgets an address nobody has seen for 90 days, so the table does not
  fill with the past.
- The Log sources card warns when fail2ban reports to AbuseIPDB or SniffCat
  itself, which sends each ban twice.

## The agents
