# RemotePower v7.4.1 — "Al1gnMatters"

A patch release for what a Docker install of 7.4.0 ran into.

Most of it is one mistake: two places that should agree about one thing, and do
not. A limit the form checked and the server did not. A port the browser used and
the server never saw. A credentials file that changed while the agent kept the old
ones in memory.

After upgrading, hard-reload the dashboard once so the new front-end loads.

## Enrolling agents

- **A server with its own certificate authority** (the Docker default) can be
  enrolled with the CA fingerprint alone. The installer fetches the CA without
  trusting the server's certificate, keeps it only if its SHA-256 is the
  fingerprint you gave, and trusts that CA for the rest of the install, with curl
  or wget. A refused CA is not left on the host. If you forget the fingerprint,
  the error says to pass one. `install-client.sh` and the macOS installer fetch
  the CA from the server's own address, port included.
- **Add host → Quick install command** shows a second line when the server has its
  own CA. It checks the CA against the fingerprint the dashboard shows before it
  fetches the installer, so nothing the server sends is trusted until they match.
  The first line cannot work against such a server, and `wget -q` hides why.
- **The port you opened the dashboard on reaches the server.** nginx used to
  forward the host name without its port, so behind a published port other than
  443 the installer's server address, the portal magic link, the passkey origin and
  the single sign-on addresses were all built without it. This fixes them all, not
  only the installer.
- **Enrolling a host again restarts its agent.** The installer wrote the new
  credentials and left the running agent on the old ones, so the host showed as
  down until you restarted the service. A running Linux agent also notices new
  credentials on disk by itself now, like the Windows and macOS agents, so
  `remotepower-agent enroll` run by hand works too.

## Docker

- **The browser terminal and the file manager** work in the image. Set
  `RP_WITH_WEBTERM=1`. It is off by default because it is an SSH client that an
  admin can point at any address the container can reach.
- **The scanner container is no longer reported as unhealthy**, and it waits for
  the server to answer before it starts polling.
- **The HTTP to HTTPS redirect names the port** HTTPS is published on, taken from
  `RP_HTTPS_PORT`.

## The dashboard

- **A host's poll interval can be set from 10 to 3600 seconds**, the same as the
  fleet default and what the agents run. The host drawer, the bulk editor and host
  profiles used to refuse anything under 30.
- **The sidebar no longer opens under a fingertip.** On a touch screen it stays
  open and the Collapse button is there; auto-hide needs a mouse or trackpad.
- **Closing the host drawer puts focus back on the host's row**, even when the
  list was refreshed while the drawer was open.
- **A recurring maintenance window can be made from the form.** Choosing
  "Recurring (cron)" shows the cron field and the duration, and editing a
  recurring window shows its cron expression and length.
- **Ten more things that stayed hidden now show:** steps 2 and 3 of the ACME issue
  wizard, the Timeline and Logs tabs of a certificate, the AI Conversation tab on
  the IaC page, the file-path field and two hints in the log alert rule dialog,
  and the "saved" badges beside the SMTP and LDAP passwords.
- **The sign-in page shows only the methods that are turned on.** The SSO, SAML
  and passkey buttons were drawn on every install, set up or not.

## AI assistant

- **Reasoning effort turns a thinking model's thinking off.** Set it under
  Settings, AI assistant, or for one prompt under its Fine-tuning. **None** sends
  `reasoning_effort: "none"`, which is what Ollama needs; a `/no_think` line in
  the prompt does not work. Left on the default, nothing is sent. See
  [ai.md](ai.md).
- **An empty answer that stopped at the token limit says why**, and names the
  setting, instead of showing an empty box.
- **Fine-tuning now reaches Mitigate, alert triage and the log sweep.** The values
  saved for these prompts were never applied. A value you saved earlier takes
  effect on the next run.

## Alerts

- **NIC errors and drops have floors of their own.** Under Settings, Alert
  parameters, the **NIC drop floor** sits next to the error floor. Leave it
  blank and errors and drops are added together, as before. Set it and they are
  judged apart; 0 turns drop alerts off. A host can have its own floors under
  Metric thresholds. The alert says what rose, and only blames the cable when
  errors rose.
- **A restart no longer looks like a burst.** After a gap in the reports the
  counts are scaled back to what a normal gap would have collected.
- **Emptying a field in Metric thresholds removes that override.**

## Drift

- **A file the host never had no longer alerts as "removed"** when it goes
  dormant.
- **A watch entry can be a folder or a pattern.** `/etc/apt/sources.list.d/`
  watches the files in the folder; `*`, `?` and `[..]` work in any part of a
  path. A file that appears in a watched folder later is drift and shows as
  *Added*. Needs agent 7.4.1 or newer.
- **A host's list can build on the default.** Start it with `@defaults` to add
  to the list the host would otherwise get, and use `-/path` to remove one of
  its entries. See [drift.md](drift.md).
- **A host profile's drift-watched files now reach the agent.**

## Upgrading

Docker: take the new `docker-compose.yml` along with the image. It passes
`RP_HTTPS_PORT` to the container (as `RP_PUBLIC_HTTPS_PORT`) and has the commented
line for the web terminal. Without it the container works as before, and the HTTP
redirect names no port.

Everything else is the usual update.

## Not in this release

- The Windows installers still read the CA from `http://<host>/ca.crt` on port 80.
  If your server's HTTP port is something else, give `install-windows.ps1` the
  address with `-Ca`. The one-line Windows install has no self-signed path.
