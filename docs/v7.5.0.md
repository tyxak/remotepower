# RemotePower v7.5.0 — "Wh0leMatters"

A release about finishing what was started. The production release is 7.4.0, so 7.5.0 carries everything from 7.4.1 to 7.4.9
as well: the Standard and Extended upgrade modes, drive sensors that follow their own disk, the second look and the typeface
option under My Account → Appearance, the container health alert, more chat destinations, and the review of the whole project
that came with 7.4.9. Their pages are in [CHANGELOG.md](../CHANGELOG.md) and the last of them is [v7.4.9.md](v7.4.9.md).

On top of that, 7.5.0 closes the gaps a second read of the whole product found. Most of them have one shape: a rule that
the code applied in most places and missed in one or two. Four-eyes approval held a command in the places that had been
remembered and let it through in about a dozen others. A restore asked for no sign-in where saving the same switch asked for one.
A guide described a promise the code did not keep. The review found fifteen Medium issues, twenty-one Low or hardening items and
three informational ones, and every one of them is fixed; one of the Medium issues is High on a Mac that asks for signed commands.
See [security-review-7.5.0.md](security-review-7.5.0.md).

## After you upgrade

- Hard-reload the dashboard once so the new front end loads.
- **Update the agents.** The agent version is 7.5.0. The canary-channel, self-update, repository-credential, host-probe, scanner and
  heartbeat-stall fixes are decided on the host.
- **If you use four-eyes approval, expect more entries under Confirmations.** A library script run, a package action, a file
  written in the file manager, a compose action, a Docker clean-up, a smart plug's power-off or cycle, a scheduled command and the
  start of a rollout wait for a second administrator when their kind is gated. Each entry now says in words what it will do. An API
  client gets the same answer as for the commands that were already held: `202` with `approval_required` and a confirmation id, or
  that result per host in a batch.
- **Restoring a backup or a configuration revision asks you to sign in again** (a fresh step-up). An API key cannot step up, so a
  key cannot restore.
- **Narrowing the gated command kinds asks for a step-up** too. If a configuration-as-code file sets `approval_gated_kinds`, the
  import lists it as refused and applies the rest; set it in Settings.
- **Ansible:** SSH host keys are remembered in the data directory (`ansible_known_hosts`). A host you rebuilt on purpose needs its
  old line removed; [provisioning.md](provisioning.md) says how.
- **Playbook content** is shown to administrators and to roles with the `script` permission only. Any other role sees the list.
- **Provisioning is on** for every installation. If you saved the old 5.x toggle as off, the stored value is ignored.
- **Monitors you assigned to a satellite** are probed by the satellite from now on. They showed "awaiting first satellite probe"
  before. Update the relay by running `packaging/satellite-setup.sh` again; `RP_SATELLITE_PROBES=0` turns probing off on one relay.
- **Maintenance windows:** browser push now obeys a window, quiet hours and an unmonitored host, and an auto-patch policy for one
  tag or one site is a window for that tag or site. If you relied on a tag policy silencing the whole fleet, make a global window.

## Four-eyes approval reaches every command

The rule was written once and applied in the places that had been remembered. A test now lists every function that writes the
command queue (29 today: 12 ask, 17 are left out with a stated reason, such as the heartbeat removing a command or the UPS emergency
shutdown) and fails for a thirtieth that does not ask. A schedule is held when it comes due, in the name of the person who scheduled
it, so nobody approves their own job. The smart plug's power-off and cycle count as a shutdown and a reboot; switching on is never
held. A file written in the file manager counts as `exec`, because a file in a cron directory is code that runs.

## The agents' data reaches the pages that can use it

The agents send far more than any one page read. A matrix of each signal against the eleven places that could use it found the read
side doing the right thing in most cells and missing a few. Closed in this release:

- **Compliance** sees security updates, a stale kernel, the patch SLA, clock synchronisation, local accounts with UID 0 or no
  password, a backup that cannot be restored and Defender switched off. Before, a host with thirty security updates waiting passed
  PCI DSS 6.3.3 and SOC 2 CC6.7.
- **The risk score** reads security updates, restart loops, a Mac's Gatekeeper and System Integrity Protection, a Windows host's
  Defender signatures, tamper protection and UAC, lapsed certificate files, local accounts and failing backup checks.
- **The Security Advisory** reads hardware, storage, kernel and antivirus data, container image CVEs and lapsed certificate files.
- **Alerts** for a Linux host's firewall and disk encryption (opt-in) and for a Mac's automatic security updates; a critical CVE in a
  container image.
- **The AI** knows what a host is, its ZFS cache and datasets, its Docker disk use and, in the digest that opens each call, eleven
  more conditions, ranked so the cap of four keeps the worst. Four MCP tools that answered empty for every host answer.
- **Fleet Query, the Data Explorer, the fleet report and the pages** gain what they lacked: encryption and security updates, ten
  health fields, Hardware and Exposure sections, the newest snapshot of a pool, when a backup was last checked, and why a container
  is unhealthy.

## What did not work and does now

Provisioning on a fresh install, monitors assigned to a satellite, maintenance windows and browser push, a local model server at
its default address, your own session when you change your password, the EDR card's count of protected hosts, six routes missing
from the API reference, and a handful of statements in the interface that the code did not keep. Each is in the CHANGELOG with the
reason.

## The whole product was read again

[security-review-7.5.0.md](security-review-7.5.0.md) says what was read and run, what was found and fixed, what is open (nothing that
attacks an installation) and what was not run.

## Smaller changes

- The upgrade mode is a checkbox in the host's own drawer, under Host settings.
- The CMDB asset dialog's tabs wrap on a phone, the Monitor header's buttons stay on the screen, and the keyboard focus ring has 3:1
  contrast in the light themes.
- Buttons in one row share a border, an inset and a radius; icon and label are 5 px apart in the Audit tab's section headers.
- Inter and JetBrains Mono ship their licence texts. B612 already did.

## Translations

1,195 values were corrected after a read of the whole dictionary in the six languages. The new strings of this release ("Last
snapshot" and the server messages) are translated; a read by a native speaker is still owed.
