# RemotePower v7.4.6 — "F1xableMatters"

A patch release for requests from the same Docker install. The first is in: #55, a host behind a NAT
firewall can be marked internal, so a service that listens on every address is not graded as exposed to
the world while the host has only private addresses. #56, #57 and #58 are added to this page as each
one lands.

After upgrading, hard-reload the dashboard once so the new front-end loads. Update the Linux
agents so they report their addresses; without that, marking a host internal changes nothing.

## A host can count as internal

A service that listens on every address (`0.0.0.0` or `::`) has always been graded **world**, and
Docker makes that the case for every published port. On a host behind a NAT firewall with no port
forwards, nothing outside your network can reach those services, so the host carried a warning that
was not an exposure.

Now an administrator can mark the host internal: click **Treat as internal** beside one of its
world sockets on **Security → Exposure**, or on the Ports card of the host. Its services that
listen on every address are graded **assumed internal**, which counts as LAN. They no longer raise
the *World-exposed ports* check, a *World-exposed service* alert or risk-score points, and the
Checks row says how many services it is not warning about.

The mark holds only while every address the host has is private. A public IPv4 address, or any IPv6
address that is not local, puts the services back to **world**, because a NAT does not protect IPv6,
and the page names the address. An agent that does not report its addresses keeps the grade at
world too, and the page says so. A new listener is still reported as before.

Turning the mark off, or a marked host gaining a public address, changes the page at once. The
alerts follow at the host's next report, and each service that is world again raises *World-exposed
service* as if it had just been opened. See [exposure.md](exposure.md#hosts-behind-a-nat-firewall).

## Suggested dependencies point the right way

The Network page suggests that one host depends on another when it sees the host connect to it.
It read every established connection as one the host had opened, so a server also showed up as the
client of its own clients: your database "depended on" the app that queries it, on a port that was
the app's own. Now the Linux agent leaves out a connection the host accepted, one whose local port
is a port the host listens on, and the suggestions list only the connections a host opened.

A host that still runs an older agent is handled by the server. It drops a suggestion when the other
end is a port from 32768 up that the other host does not listen on, as long as that host reports its
whole list of listening ports. A suggestion it cannot judge stays, so you are still asked. Update the
Linux agents to stop the wrong ones at the source.

## Resolving an alert refreshes the host

Needs attention and Checks show what a host last reported, and an agent sends its system information only
every ten polls. An alert you resolved by hand could therefore sit beside a Needs attention entry for
something the host had already put right, such as a failed unit you reset, for several minutes. Resolving
an alert now asks its host to report on its next poll, so the pages catch up within one poll. A host with no
agent is not asked, a host is asked at most once in two minutes, and an alert that closes on its own does
not ask, because the host has just reported. Update the agents so they read the request.

This is a first step toward one list that shows each problem once across Alerts, Needs attention and
Checks. That list is not built yet.

## What this release does not do

The Windows and macOS agents do not report their addresses yet, so a Windows or macOS host marked
internal keeps the grade its agent gave. There is no list of trusted networks and a host does not
inherit the mark from the host it is connected to; the mark is one switch per host.

## Security review

The internal-host switch was reviewed against 7.4.4, the last reviewed release, in a review written
for it as v7.4.5 before that version was folded into this one. It found two issues, both low, and
both are fixed:

- A request to the new route that did not say true or false turned the switch off. It fails
  closed, but a request that does not say what it wants must not change a host's grade. The route
  answers 400 now.
- The Exposure page and the Checks row raised on a stored port list that is not a list of maps.
  Only a hand-edited or imported store holds one. Both skip it now.

The switch held up under the rest: a tenant administrator can mark the tenant's own hosts and no
others, a role that holds every action permission cannot mark one, a host cannot set its own
switch or the mark on its sockets, a hostile report of addresses or ports answers 200 and leaves
bounded rows, toggles racing reports leave the rows and the switch in agreement, a host's text
stays text on every page that prints it, and the assistant sees a host's addresses only when the
install sends addresses. See [security-review-7.4.5.md](security-review-7.4.5.md).
