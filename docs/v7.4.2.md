# RemotePower v7.4.2 — "Re4lMatters"

A patch release for four reports from a Docker install of 7.4.1.

In each, the dashboard says one thing and the host is doing another.

After upgrading, hard-reload the dashboard once so the new front-end loads.

## An alert for a stopped container closes when it runs again

A container you stop leaves the agent's list, since the agent reports the
containers that are running, and RemotePower raises *Container stopped* with the
status `gone`. That alert never closed, however long the container ran again.
Two things were missing. The check for a container coming back only looked at
containers that were still in the previous report, and a container that starts
again is a name no report holds. And when every container on a host was stopped
at once, as a nightly backup does, the next report had nothing to compare with
and was skipped.

The names that have an open alert are now kept with the host. A name that is
running again closes its alert, also when the container was removed and created
again under the same name. Alerts that were already open when you upgrade close
on the first report after it, for the containers that are running.

A container that comes back under a different name is a different container, so
its old alert stays open until you resolve it or exclude it (below).

Inside a maintenance window the alert is recorded and the stop notice is held.
The recovery notice is held too, and the alert still closes.

The agent still lists only running containers. Listing stopped ones as well
would put every one-shot container on the list, and a host with many of them
could push its long-running containers past the 100 a report holds.

## Container excludes match the image

`container_alert_excludes` takes name substrings. An entry that starts with
`image:` is read against the image instead, which is what you want for helper
containers that exit by design and get a random name each run:

```json
{"container_alert_excludes": ["pause", "image:ghcr.io/getarcaneapp/tools"]}
```

`image:ghcr.io/getarcaneapp/tools` matches that image whatever its tag; add a tag
(`image:ghcr.io/getarcaneapp/tools:1.2`) to match one tag. Case does not matter in
an image entry. A container kept out this way raises no stopped or restart-loop
alert, and it is not counted in the Needs Attention list or the dashboard's
stopped-containers widget. Those two did not use the list before.

The list is fleet-wide. Edit it on **Monitoring → Tuning**, in the **Container
exclude list** card: one entry per line, then **Save exclude list**. Only an
administrator can change it. It was reachable only through `POST /api/config`
before, which takes the same list. Each entry also shows in **Everything
currently silenced** on that page. See [containers.md](containers.md).

## SNMP memory leaves out the cache

net-snmp counts the page cache and the buffers as used in the "Physical memory"
row, and lists them again as "Cached memory" and "Memory buffers". A FreeBSD
firewall with 7,454 of 7,918 MB "used", most of it cache, read 94% and raised a
memory alert. RemotePower now takes those two rows off, so the same host reads
38%.

The memory alert, the history graph, the Hosts page and the SNMP tab all use that
figure. The tab shows a Memory block with the share in use, the cache and buffers
and the total, and says what the host itself reports. A host that lists no cache
rows is read as it reports, and a host that really is short
of memory still alerts.

The figure can still be higher than the host's own `top`. The poll reads one
table, and a host may keep reusable memory that it does not put in it. The OID
browser has a preset for the storage table and a new one for the UCD memory group,
so you can see what your host does report. See
[agentless-devices.md](agentless-devices.md).

## A host's card shows its integrations

A host with no agent and no SNMP, a Hubitat hub for one, gets its health from the
integrations bound to it. Its card used to show nothing but whether it answers.

Open the host, go to the **Audit** tab, and **Integrations on this host** lists
every instance bound to it (*Runs on host*), worst first: the status, when it was
last checked, the latest values, a trend line for each number and how the last
checks went. The section opens by itself when something is bound to the host.

The trend is drawn from the last 100 checks, about eight hours at the default
five-minute cycle, and it starts when you bind the instance: the numbers are kept
only for an instance bound to a host. The address and the credentials of an
instance are never sent to the card. See [integrations.md](integrations.md).

A probe that reads a JSON field from a service which prints `NaN` when a sensor
read fails used to stop RemotePower saving the results of every integration, for
as long as it kept doing so. Such values are now stored as empty and the rest are
saved.

## The host drawer gives focus back

Closing the host drawer returns focus to the control that opened it. It did not
when the drawer had been opened twice in a row, by a key handler and the click it
makes or from the command palette: the second open remembered a button inside the
drawer, and closing left focus on nothing. A keyboard user lost their place.

## Upgrading

Nothing to do beyond the usual update. The agents are unchanged.
