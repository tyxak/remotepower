# RemotePower v7.4.9 — "Ch0iceMatters"

A release about the choices you make on a host, and about checking the whole product before it ships. A host can run its
upgrades in a Standard or an Extended mode. A hard disk and a SATA SSD behind the same controllers keep their own temperature
lines. An update that Ubuntu is still phasing in is no longer counted as pending. Most of that came from the replies to #54 and
to a question in Discussions (#30).

The rest is a review of the whole project, not only of what changed since 7.4.8. It found five High, sixteen Medium and ten Low
or hardening issues, and every one of them is fixed. The review lists what is left, which is nothing that attacks an
installation. See [security-review-7.4.9.md](security-review-7.4.9.md).

## After you upgrade

- Hard-reload the dashboard once so the new front end loads.
- **Update the agents.** The agent version is 7.4.9. The drive sensors, the patch count, the kept-back package names and the
  agent security fixes are all decided on the host.
- **If you used ACME with a DNS credential saved in Settings, rotate that token.** Before 7.4.9 it was stored in the host's
  command history, which every signed-in role can read, and a backup can hold a copy.
- **Docker:** the app server and the daemons run as `www-data` now, not as root. An existing volume needs no step. If you use
  `docker exec` for a command that writes to the data volume, add `-u www-data` so it does not leave files owned by root.
- **Sign out** ends the session on the server now. A token that someone copied before you signed out stops working.
- **Maintenance windows:** a window saved with a day or month name such as `SUN` never opened, and it opens now. Look at the
  windows you edited by hand.
- **If you saved central DNS credentials for ACME and you have tenants, rotate that token.** Before 7.4.9 an ACME request for a
  tenant's own host put the operator's DNS credentials in the command for that host.
- **Tenancy:** on an installation with tenancy on, the operations that affect the whole installation are for the platform
  operator only (a service restart, a backup and its restore, the data store's migration, the server's certificate, the operator's
  hypervisors and DNS zones among them), and so are the pages and stores of the organisation that runs the installation: the
  monitors, links, calendar, billing, time tracking, sites, contacts, integrations, DNS, dead-man jobs and needs-attention
  suppression rules answer users of the default tenant and refuse every other tenant. What names no host (an alert about a monitor,
  the settings document's lists, the audit trail of other tenants) is the installation's. A ticket belongs to the tenant of its host
  (or of the account that opened it). If a tenant's users relied on one of those pages, they lose it; that was the leak. See
  [security-review-7.4.9.md](security-review-7.4.9.md) and the [tenancy guide](scaling.md).
- **Stored data:** a row of the wrong shape in a store is left out of what a page reads, and the file as it was is kept in the
  `quarantine/` folder of the data directory (the last 20), with one line on stderr naming the store. Look there if a row seems
  to have vanished.

## Choose how a host upgrades

`apt-get upgrade` keeps back an update that needs a package that is not installed yet, such as a new kernel image or the split
`linux-firmware` packages. It installs nothing for it, prints no error and exits 0. A host can now run its upgrades in one of
two modes:

- **Standard** runs `apt-get upgrade`, as before. It is the default.
- **Extended** runs `apt-get upgrade --with-new-pkgs`. It installs the new packages such an update needs and removes nothing.

Choose the mode in the host's Patch Report, which also names the packages apt keeps back on that host, or for many hosts at once
in Bulk actions. A host in Extended mode carries an **Extended** badge on the Patches page. The mode applies to the patch button,
auto-patch (flat and staged), scheduled upgrades, rollouts, the compliance fix for pending updates and the autonomy loop. A host
that does not use apt ignores it. Only administrators set it, and a change is audited. See [patches.md](patches.md#upgrade-mode).

## A drive sensor follows its own disk

7.4.8 held every `drivetemp` sensor to the lines for any other drive, because the sensor's name does not say hard disk or SSD.
The Linux agent now finds the disk behind each sensor from its SCSI address, and the sensor is held to that disk's lines: the
disk's own line (kept against its serial number), then the host's and the fleet's for its type, then the lines for any other
drive. The Thermal page names the disk in the sensor's row (`sda · SSD`) and says *disk not identified* when the agent could not
tell. The risk score follows the same lines, and so does the temperature list in the host drawer, which used to colour anything
at 75 °C or more whatever the settings said. See [thermal.md](thermal.md).

## What 7.4.8 got wrong on Ubuntu 22.04

7.4.8 counted every package apt keeps back, except the ones held with `apt-mark hold`. On Ubuntu 22.04 that included an update
Ubuntu was still phasing in to the host, which arrives by itself and which neither upgrade mode installs before then, so the
host read as having an update that nothing could clear. The agent now asks apt the same question with phasing ignored and
leaves such a package out. Ubuntu 24.04 and Debian 13 list deferred updates under a heading of their own and were not affected.
This was found by running the agent against real apt (Ubuntu 22.04, Ubuntu 24.04 and Debian 13), which 7.4.8 had not been.

## The whole project was reviewed

Seven reviews ran side by side on a seeded copy of the product: who can reach what on every route, hostile input on every route,
the three agents and their installers, the web client and the web server headers, the interface, the documents, and a map of what
the agents send against where it is used. Scanners ran beside them. Every fix has a test, and each test was run against the code
with its fix taken out. The fixes you will notice:

- **A viewer could rewrite a host's watched services and log-watch rules** by changing the HTTP verb of one request. Only POST
  checked the permission. Every verb is checked now (High).
- **The agents.** Two High issues in the Linux agent: a web request target that kept the threat sensor busy for seconds, and
  host config and SSH key collection that followed links in a user's `~/.ssh` as root. Also a restore drill sample path that
  could run a command through `tar`, and several Medium issues in the agents and installers, among them a CA pin that checked
  the first certificate and trusted the whole file. The CHANGELOG lists them all.
- **Sign out** did not end the session on the server. It does now, and the page also forgets the hosts you opened recently, your
  favourites and your unsent drafts.
- **A host's SCAP report** opened inside the dashboard's own origin and lost its sandbox. It opens from a link the server serves
  with its own policy. The page asks for the link first, and it works for one minute.
- **A DNS provider token** no longer reaches the command history, and four AI features (the mitigate step, alert triage, the
  log-sweep analysis and the AI exec proposal) redact logs and command output before they send them, as every other AI request
  does.
- **Tenants.** A tenant administrator could reach operations on the whole installation, and other tenants' sessions, schedules,
  rollouts, host links, command history, image updates and webhook log. A tenant's users could also read every tenant's tickets
  and the operator's monitors, links, calendar, invoices, quotes, sites and contacts. They cannot now.
- **A row of the wrong shape** in a store (a null in the alerts, a number where a map belongs) answered 500 on the home, problems,
  alert and risk pages for everyone, and stopped the periodic work that read it. The shape of 134 stores is stated once and
  checked where a store is read. A hand edit, an import or a restore can no longer take a page down.
- **Hostile input** no longer answers 500 on the routes a stranger or a host can reach: a token with a character outside ASCII, a
  lone surrogate in a JSON string, `Infinity` and a 400-digit number.
- **Docker:** the app server and the daemons run as `www-data`. **GitHub Actions** are pinned to commits, and Dependabot waits a
  week before it proposes a release.

Every High and Medium finding is fixed. What the review lists as open is smaller and none of it attacks an installation: some
interface leftovers and ten places that could use a signal the agents already send.

## Smaller changes

- The Mitigate CVE diagnostic lists the packages apt keeps back and the security updates an Extended upgrade would add. It
  listed security updates by their `Inst` lines, which a kept-back kernel never has.
- A junk number in the SLO store no longer fails the whole Prometheus scrape. The sample is left out, as in every other family.
- The Advisory has a finding for an unencrypted Linux disk, as it already had for FileVault and BitLocker. It is off until you turn
  on the disk encryption check.
- The AI digest knows about security updates, memory errors and an unreachable gateway, and the hardware line shows GPU use.
- A card's hint no longer touches its first row, a settings row no longer touches the next field, the focus ring is clipped far
  less often, and an Arabic checkbox label sits next to its box. The notification routing matrix's checkboxes have names.
- The Logs page printed "≥ undefined" for a rule saved without a threshold.
- The fields of an integration card, the pause duration of a DNS blocker card and the format of a webhook destination have names
  for a screen reader (57 controls had none), and the host drawer no longer logs an error for a host without SNMP.
- Swagger UI 5.34.1 (a bug-fix release) serves the API reference.
- The demo data carries the Extended mode, kept-back packages and named drive sensors.

## Translations
