# RemotePower v7.4.9 — "Ch0iceMatters"

A release about the choices a person makes on a host. A host can run its upgrades in a Standard or an Extended mode, and a hard
disk and a SATA SSD behind the same controllers keep their own temperature lines. It also corrects one thing 7.4.8 got wrong on
Ubuntu 22.04. Most of it came from the replies to #54 and to a question in Discussions (#30).

After upgrading, hard-reload the dashboard once so the new front-end loads. Update the Linux agents too: the drive sensors, the
patch count and the kept-back package names are decided on the host.

## Choose how a host upgrades

`apt-get upgrade` keeps back an update that needs a package that is not installed yet, such as a new kernel image or the split
`linux-firmware` packages. It installs nothing for it, prints no error and exits 0. A host can now run its upgrades in one of
two modes:

- **Standard** runs `apt-get upgrade`, as before. It is the default.
- **Extended** runs `apt-get upgrade --with-new-pkgs`. It installs the new packages such an update needs and removes nothing.

Choose the mode in the host's Patch Report, which also names the packages apt keeps back on that host, or for many hosts at once
in Bulk actions. A host in Extended mode carries an **Extended** badge on the Patches page. The mode applies to the patch button,
auto-patch (flat and staged), scheduled upgrades, rollouts, the compliance fix for pending updates and the autonomy loop. A host
that does not use apt ignores it. Only administrators set it, and a change is audited. See [patches.md](patches.md#upgrade-mode).

## A drive sensor follows its own disk

7.4.8 held every `drivetemp` sensor to the lines for any other drive, because the sensor's name does not say hard disk or SSD.
The Linux agent now finds the disk behind each sensor from its SCSI address, and the sensor is held to that disk's lines: the
disk's own line (kept against its serial number), then the host's and the fleet's for its type, then the lines for any other
drive. The Thermal page names the disk in the sensor's row (`sda · SSD`) and says *disk not identified* when the agent could not
tell. The risk score follows the same lines, and so does the temperature list in the host drawer, which used to colour anything
at 75 °C or more whatever the settings said. See [thermal.md](thermal.md).

## What 7.4.8 got wrong on Ubuntu 22.04

7.4.8 counted every package apt keeps back, except the ones held with `apt-mark hold`. On Ubuntu 22.04 that included an update
Ubuntu was still phasing in to the host, which arrives by itself and which neither upgrade mode installs before then, so the
host read as having an update that nothing could clear. The agent now asks apt the same question with phasing ignored and
leaves such a package out. Ubuntu 24.04 and Debian 13 list deferred updates under a heading of their own and were not affected.
This was found by running the agent against real apt (Ubuntu 22.04, Ubuntu 24.04 and Debian 13), which 7.4.8 had not been.

## Smaller changes

- The Mitigate CVE diagnostic lists the packages apt keeps back and the security updates an Extended upgrade would add. It
  listed security updates by their `Inst` lines, which a kept-back kernel never has.
- A junk number in the SLO store no longer fails the whole Prometheus scrape. The sample is left out, as in every other family.

## Translations

The upgrade mode and the drive sensor labels are translated into the six languages. They were written without a native reader
and are due a read by one.
