# RemotePower v7.4.4 — "Spec1ficMatters"

A patch release for one request from the same Docker install, #54: temperature lines for each
drive, set for one drive, for one host or for every drive of a type, where the most specific line
wins.

After upgrading, hard-reload the dashboard once so the new front-end loads. Update the Linux
agents to get the drive type; the lines themselves work without it.

## Temperature lines for each drive

A hard disk, a SATA SSD and an NVMe drive run at different temperatures, and until now a drive's
temperature was judged only by the fleet's hot and critical pair (75 and 85 °C), in the risk score
and on the Thermal page. A hard disk at 60 °C raised nothing, and no alert came from a drive's
temperature at all.

Now you can set a warning line and a critical line, in °C:

- **For every drive of a type,** under **Settings → Alert parameters → Drive temperature**: a pair
  each for hard disks, SATA SSDs and NVMe drives, and a last pair for any other drive.
- **For one host,** under **Metric thresholds** in the host's menu, with the same four pairs.
- **For one drive,** on the host's Hardware tab, in the two boxes beside the drive's name. The
  lines are kept against the drive's serial number, so they follow it when its letter changes.
  Administrators only.

The most specific line wins, the warning and the critical line one at a time: the drive's own, the
host's for the type, the host's for any drive, the fleet's for the type, the fleet's for any drive.
An empty box follows the level below it, shown in grey. Every line is off until you set it, so
upgrading alerts on nothing new.

A drive over a line raises one alert for that drive, for example *Drive Pool disk 2 (/dev/sdd, sn
WD-1234) CRITICAL on nas01: 52°C*. It closes when the drive cools, and it is muted, held by a
maintenance window and listed in Needs attention like the other disk problems. The *Temp* column in
the SMART table turns amber or red against the same lines.

Two things stay as they were. The risk score and the Thermal page still judge every sensor against
the fleet's hot and critical pair. And the Windows agent does not send a drive type yet, so its
drives use the lines for any drive. See [disk-health.md](disk-health.md#temperature-lines-for-each-drive-v744).

## A sensor you ignored stays quiet

The ignore list for a host's temperature sensors was read from a copy of the host that did not carry
it, so a sensor you had switched off, such as a dead pin, went on raising *High temperature*. It
works now.
