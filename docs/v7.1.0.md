# RemotePower v7.1.0 — "G4tewayMatters"

A release about the front door.

Reaching a host over SSH used to mean opening a port on it, or keeping a jump
host of your own. Now RemotePower is the jump host: your own `ssh` client, one
gateway, and a tunnel that each opted-in host opens outward — no inbound port
on the host at all.

The addresses that knock on that door, and on every host's sshd, now get looked
up against two public reputation services, reported back if you want to help
other people, and blocked for a while if they are known to be abusive.

And both halves — who is attacking a host and who logged in to it — reach
every place that describes a host, rather than living on a page of their own.

After upgrading, hard-reload the dashboard once so the new front-end loads
(service-worker cache `remotepower-shell-v7.1.0`).

## The SSH gateway

Add a key on **Access → SSH gateway**, copy the `~/.ssh/config` block the page
gives you, and `ssh web01.rp` works from your laptop. What happens underneath:

- The gateway accepts public-key logins only. There is no shell on it and no
  port forwarding beyond the one hop to the host you named.
- The host's agent has already opened a tunnel outward to the gateway, and the
  gateway hands your connection down it to that host's own sshd on loopback.
  The tunnel cannot reach any other port or any other machine.
- Every login and every connection is asked of RemotePower: your `ssh`
  permission, your role scope and tenant, whether the host has opted in, and
  whether it is quarantined or decommissioned. It is asked again for each
  connection, so taking something away takes effect on the next connect.
- Every session is recorded: who, which host, from which address, for how long,
  and how much data each way.

It is off by default, and the host has the last word — a host can refuse the
tunnel whatever the server says. Install it with
`install-server.sh --with-sshgw`; [sshgw.md](sshgw.md) has the details.

## Threat intel

When an address crosses the brute-force threshold on any host, RemotePower now
checks it against AbuseIPDB and SniffCat — one or both, with your own keys —
and keeps the answer for a day. Then, if you have switched them on:

- **Report.** The address goes back to each service once a day with the attack
  categories and a count. Never a hostname, a user name or a log line.
- **Block.** If its score reaches your threshold, the attacked host drops its
  traffic for the hours you choose. The block goes through the ordinary command
  queue, so maintenance windows, quarantine, audit mode and four-eyes approval
  all apply, and it is lifted again on its own.

Some addresses are never blocked and never reported: private ranges, the
fleet's own addresses, your allow-list, a never-block list you keep, and
anywhere someone signed in to RemotePower from in the last 30 days.
**Security → Threat intel** shows every attacker, which hosts it went after, and
what happened. See [ip-intel.md](ip-intel.md).

## Attacks and access, everywhere a host is described

A page of its own is where a fact goes to be forgotten. So:

- The **Security Advisory** puts the known-abusive sources first and says
  whether each one is blocked.
- The **risk score** gains two factors: a host under brute force, and a
  known-abusive attacker that is not blocked. Both weights are tunable.
- The **Data Explorer** can ask about attackers and gateway sessions, and about
  USB devices, logged-in users and the gateway opt-in on devices.
- The **fleet report** gains a *Threats and remote access* section, in the
  document, the CSV and the email.
- The **AI assistant**, the **Prometheus** export, the **knowledge index**, the
  **compliance evidence** and the **Timeline** carry the same facts.

## One body size, one heading size

Body text sat at three sizes half a pixel apart — 13.5 px prose, 13 px tables
and buttons, 12.5 px fields and subtitles. Side by side that reads as a mistake
rather than a hierarchy. It is 13 px everywhere now, and every card and section
heading shares one size. Text fields and selects use the interface font, so a
filter box and the buttons next to it look like one row.

Alert rows got the same treatment. A row could carry eleven buttons, which
wrapped to three lines and still pushed the table past its card. Triage, Fix,
Mute and Resolve stay on the row; the rest live in a labelled **More** menu.

## Edits saved with PUT work again

The shipped nginx configuration allowed GET, POST, DELETE and PATCH on the API.
The dashboard saves about thirty kinds of edit with PUT — schedules,
maintenance windows, sites, tenants, the report schedule — and on a standard
install nginx refused every one of them. It allows PUT now, and a test checks
the configuration against every method the dashboard sends.

## Translations, and what a page-by-page walk found

The Settings pages used to be translated one fragment at a time, which put the
words in the wrong order in German, Hindi and Arabic. About 220 Settings
paragraphs are now translated as whole sentences in all six languages. A walk
through every page in a browser then found the rest: about 1,700 more strings
are translated, three page subtitles that showed English in every language now
translate, and French sets its space before `;`, `:`, `!` and `?` even next to
markup.

The same walk, at phone width, found that the top bar was wider than a 390 px
screen, so every page scrolled sideways. It fits now.

Smaller fixes from it:

- Guides open in a viewer over the page, and links between guides and
  `#section` links now work inside it. A link with a section used to reload the
  whole app.
- A risk factor shows a name such as "Known exploited CVEs" instead of
  "cve kev".
- The Threat intel status column and the Container image updates subtitle
  translate.

## Security

Ten issues, all found before release and all fixed in it. The biggest: on an
install with multi-tenancy switched on, a tenant admin could change state that
belongs to the whole install, including restoring a configuration from before
tenancy was enabled. The full write-up, with what was reviewed and how, is in
[security-review-7.1.0.md](security-review-7.1.0.md).

One setting is new because of it: **Dashboard public URL** under Settings →
Notifications. Links in outgoing email are built from it, never from the
address a request arrived on, and the one-click Acknowledge / Resolve links in
alert emails need it.
