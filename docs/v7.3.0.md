# RemotePower v7.3.0 — "Edg3Matters"

A release about the edge.

Threat intel used to learn about an attacker from your own hosts' logs.
Cloudflare refuses requests before they reach a host, and a honeypot Worker
catches scanners that no host log ever sees, and neither told RemotePower. Now
both do, so RemotePower can be the one place that reports, with the evidence
behind each report.

Reading does not ban anything: whatever you already use to ban keeps doing it.
The one thing this release writes is an optional Cloudflare IP list, which does
nothing until a rule of yours uses it.

After upgrading, hard-reload the dashboard once so the new front-end loads
(service-worker cache `remotepower-shell-v7.3.0-49`).

## Edge sources

Switch them on under **Security → Threat intel → Edge sources**. They are off
until you do.

RemotePower calls the Cloudflare API with a **read-only** token, every ten
minutes, and reads two things:

- **Cloudflare's firewall events**: the requests Cloudflare refused, by address
  and by the mechanism that refused them.
- **Your honeypot Worker's log**: the traps a visitor tripped, and whether your
  Worker banned the address.

What it keeps is a count, a mechanism or trap, an address and a time. The
request path and the user agent are never fetched.

A Free plan has no grouped view of the firewall events. When Cloudflare refuses
it, RemotePower reads that zone's events one at a time and groups them itself,
asking for the address, the action, the source and the rule only. Each zone is
read on its own, so a zone that is refused is named on the **Edge feeds** card
and does not hold back the others.

### What counts

Only a refusal by a mechanism that means "this looked like an attack": managed
rules, your own custom rules, rate limiting, HTTP DDoS protection and the bot
products. Challenges, country and ASN rules, the security level, IP access rules
and rules that also block an IP list are set aside, and the **Edge feeds** card
says how many of each. An IP access rule is a ban somebody else already decided,
and a rule that also blocks an IP list refuses addresses for being on a
community blocklist. Neither is something the address did to you.

### The honeypot

An address your Worker banned is reported at once, like one fail2ban banned.
Decoys named only in `robots.txt` and crawlers that claim to be a search engine
are filed as bad web bots. Using a credential the honeypot handed out, and
signing in to a decoy service, are new classes of their own. A one-hit report
reads `using a credential planted in a decoy file: 1 attempt within 1 minute,
seen by edge honeypot (reported by RemotePower)`.

### Test connection

Press it before you switch the feeds on. It tries each thing they need, with the
stored token or the one you typed, and a missing permission shows as exactly
that. It also lists the zone's custom rules and marks the ones that name an IP
list.

## Edge blocklist

RemotePower can keep one Cloudflare IP list up to date, the way a script such as
Cloudflare-WAF-Expressions does, so a rule that says `ip.src in $your_list` keeps
blocking what your sources report. Switch it on under **Security → Threat intel →
Edge blocklist**. It is off until you do, and it uses a second token that can edit
lists.

The list is built from your own entries, the addresses RemotePower found, AbuseIPDB's
blacklist and SniffCat's blacklist, in that order when the list is full. RemotePower
writes the list and nothing else: it never creates, edits or deletes a rule.

- **A list it did not create is left alone.** The card says `Needs to be taken
  over`. **Preview** shows what taking it over would change and writes nothing, and
  **Sync now** asks before it replaces anything.
- **Your own addresses never go in.** Your hosts, the allow-list, recent RemotePower
  logins, the never-block list, Cloudflare's addresses and private addresses are
  left out, and so is a network that overlaps one of them.
- **A sync that would empty the list or cut it by more than half is held**, and so
  is one where a source failed and has no copy under three days old. **Sync
  anyway** goes ahead when you mean it.
- **The ceiling is yours and the account's.** The list stops at **Most entries in
  the list**, less what your account's other lists use.
- **Downloads are rationed.** Each blacklist is downloaded at most four times a
  day, and its last copy is used in between.

Step by step, including the token and taking over a list another tool keeps: [edge-sources.md](edge-sources.md#edge-blocklist).

## The firewall log

Linux agents with the log sensor on read `/var/log/ufw.log`, or `kern.log` when
there is none. An address counts as a scan when, within a minute, it tried four
different ports or had fifteen packets refused. Only inbound TCP counts, because
the source of a UDP or ICMP packet is what a flood forges.

## Reports

A single hit now reads `1 attempt within 1 minute`. A message you wrote yourself
is sent as you wrote it.

The log sensor no longer counts a sign-in to a JSON login API as a failed login.
Under `/api/` only an error status (400 and up) counts, because such an API
answers a right password and a wrong one alike with 200. Before this, everyone
who signed in to a RemotePower instance was recorded as login brute force. Form
logins keep the old rule. This was present in 7.2.0, so upgrade the agents if the
log sensor is on.

## If other scripts report the same things

Stop them once these feeds work, so each address is one report with all the
evidence. A report the service refuses as a repeat is counted as done, so
nothing breaks while both run. Keep whatever bans.
